# Resolve a git conflict across code and Unity assets

`$ARGUMENTS`: optional priority areas; else resolve everything conflicted. Requires unmerged paths (`git diff --name-only --diff-filter=U` non-empty); none → stop and say so. Run by a dispatched agent, the report is the `agent-protocol` envelope and every "ask" below is `Status: Needs-decision`; run in the main session, report to the GD in Vietnamese.

1. **Context** — name the operation from `git rev-parse --git-dir`: `MERGE_HEAD` merge, `rebase-merge/`, or `rebase-apply/` without `rebase-apply/applying`, rebase (with it: `git am`, same stage meaning as cherry-pick), `CHERRY_PICK_HEAD` cherry-pick, `REVERT_HEAD` revert, none of these → stash apply/pop. Stage `:2:` is `HEAD` and `:3:` the incoming change; in a rebase `HEAD` is the upstream being rebased onto plus the commits already replayed, and `:3:` is the branch's own commit being replayed. Name sides by that, never by "ours/theirs". Per conflicted path read all three versions (`git show :1:<path>` base, `:2:`, `:3:`) before touching markers: markers do not show intent.
2. **Classify each file** — C#; Unity YAML (detect by `%YAML` header, not `.meta`); Addressables (`AddressableAssetSettings*.asset`, groups under `Assets/AddressableAssetsData`); `.meta`; text/docs; binary (no textual diff).
3. **Classify scope** per hunk against the base. Either side does something the other lacks (new method, member, event hookup, `Game.Core.*` rule, prefab child/component, SO field, Addressables entry) → **big**. Pure style with identical behaviour → **small**. Never assume equivalence without reading both diffs against the base.
4. **Big: feature-preserving** — combine so every feature-bearing addition from either side survives. Only a same-line/field collision with incompatible changes becomes a small-scope decision (step 5); the rest of the file still merges additively. A true contradiction of intent → flag for `technical-architect`, never guess a winner.
5. **Small: standards** — pick the side that already matches `csharp-standards` (`references/coding-principles.md`, `references/code-style-and-layout.md`), cite the clause, fix the losing side up. Neither compliant → write the compliant form.
6. **Unity YAML** — a wired `merge=unityyamlmerge` driver already ran during the operation: a conflict left on the file means it failed, and the working file then holds the driver's output, not markers — on every clashing field the left (theirs) value, so it looks resolved and passes step 10. Never stage it: `git checkout -m <path>` restores the markers, then continue from the stages below. Otherwise run UnityYAMLMerge once on the three stages, written outside the working tree (tool path and argument order: `git-unity-repo` → `references/scene-and-prefab-conflicts.md`). Write each stage byte-exact from Bash, `git cat-file blob :<n>:<path> > <file>`: PowerShell redirection re-encodes and rewrites line endings. Run it as `timeout 120 '<tool>' merge -h -p --fallback none <base> <stage-3> <stage-2> <out>` (Bash): without `-h` and `--fallback none` an unresolved conflict opens a dialog or GUI tool and the run hangs. Exit 0 → copy its output over the path; timeout or non-zero → it failed and its output is discarded (exit 2 writes theirs on each clash with no markers). Add `-o <clash-file> --describe` to list what clashed. Never `git mergetool`: it prompts, and its backups become `*.orig` assets. Still conflicted or tool absent → merge by hand at GameObject/component/field level (steps 3–5), never across a `--- !u!` document boundary: every component and serialized field either side added survives; only a same-field value clash is the small conflict. Never invent a `fileID`; reuse the one a side assigned. Whatever must be redone in the Editor is listed for `gameplay-engineer`.
7. **`.meta`** — never hand-edit or regenerate a GUID. Keep the GUID the resolved content and the repo's other references point to (`grep -rl "<guid>" Assets Packages ProjectSettings` first). Both sides created different assets at one path with different GUIDs → real clash: keep both under distinct paths and rewire (step 9).
8. **Addressables** — merge entry by entry; every entry either side added keeps address, labels and group. A duplicate address or schema mismatch is fixed now.
9. **Reference-wiring pass** — for every touched prefab/scene/SO, grep each `fileID`/`guid` it references and confirm the target exists post-merge, checking both sides' pre-merge references (a component one side added referencing an object the other added is the likeliest miss).
10. **Verify** — on the resolved paths, `grep -nE '^(<{7}|>{7}|\|{7})( |[[:space:]]*$)|^={7}[[:space:]]*$'` prints nothing (diff3 `|||||||` included; `[[:space:]]` absorbs a CRLF checkout's `\r`; a longer `===` run in Markdown is not a marker). Apply the `/review-code-risks` lens to resolved `.cs`. Editor checks come after every working-tree write, with the Editor closed during those writes (`git-unity-repo` step 10): compile-check C# (Unity ladder in `core.md` Tools, or `dotnet build`) and, for touched assets, open the project and read the Console for missing-script/reference errors. No Editor reachable → `Not verified`, `Next:` the owning engineer.
11. **Stage and report** — `git add` only resolved files. Report per file: features combined, which side's style won and why (clause), references rewired, what verification ran. Ask before `git commit` or the operation's `--continue` — once per operation: an approved `--continue` carries through later stops that need no big-scope decision.
12. **Multi-stop operations** — a rebase or a multi-commit cherry-pick stops once per conflicting commit: repeat steps 1–11 at each stop (stages change per commit), then `--continue`. The same conflict replayed at several stops: pass `-c rerere.enabled=true` on the starting command and on every `--continue` (it records at the conflict and at the commit), and still re-verify each reused resolution. Editor checks run once, after the last stop; never open the Editor between stops, since each `--continue` rewrites the tree. A stash apply/pop conflict keeps the stash entry: drop it only after the result is confirmed (`git-safety-anchor` stash row).

## Never
- Discard either side's feature to make the merge look clean.
- `git checkout --ours/--theirs` on a whole file before confirming the discarded side carries nothing the kept one lacks.
- Commit or push automatically.
- Claim wiring or compile verification that did not run.
