## Choosing a transport

| Transport | What it decides | Source |
|---|---|---|
| `UnityTransport` (default) | NGO's shipped, actively maintained transport — handles connection management, packet ordering, data integrity, flow control, congestion management. Recommended for all new projects. Assign it via the NetworkManager Inspector's **Select Transport** dropdown, which sets `NetworkConfig.NetworkTransport`. | [Transports](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/transports.html) |
| UNet Transport | Deprecated — unsupported since Unity 2022.2. Per this project's Obsolete-API rule, never wire this into new work even if old sample code still references it. | [Transports](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/transports.html) |
| Custom / community transports | Any subclass of the abstract `NetworkTransport` can be dropped in — NGO's community-contributions repository ships others (e.g. Steam-based transports referenced in the FAQ below). | [Transports](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/transports.html) |
| `SinglePlayerTransport` | Runs a hosted session with no network overhead for genuine offline single-player, without touching gameplay scripts — start it the same way as any host, via `StartHost()`. Add the component to the NetworkManager GameObject and set `NetworkManager.NetworkConfig.NetworkTransport = singlePlayerTransport` before calling `StartHost()`. | [Single player](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/singleplayer.html), [SinglePlayerTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Transports.SinglePlayer.SinglePlayerTransport.html) |
| `SinglePlayerTransport.StartClient()` | Always returns `false` — this transport is host-only; client connections are unsupported by design. | [SinglePlayerTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Transports.SinglePlayer.SinglePlayerTransport.html) |
| `SinglePlayerTransport.GetCurrentRtt(ulong)` | Always returns `0` — everything is local, there is no real network hop to measure. | [SinglePlayerTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Transports.SinglePlayer.SinglePlayerTransport.html) |
| Switching to multiplayer | Swap the assigned transport to `UnityTransport` (or another `NetworkTransport`) before the session ever calls `StartClient()`/`StartServer()` for real networking — `SinglePlayerTransport` cannot be reused for that. | [Single player](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/singleplayer.html) |
| Abstract contract (`NetworkTransport`) | Any implementation must provide `ServerClientId` (the `ulong` constant standing for "the server"), `IsSupported`, `Initialize(NetworkManager)`, `Shutdown()`, `StartServer()`, `StartClient()`, `Send(ulong, ArraySegment<byte>, NetworkDelivery)`, `PollEvent(out ulong, out ArraySegment<byte>, out float)`, `GetCurrentRtt(ulong)`, `DisconnectLocalClient()`, `DisconnectRemoteClient(ulong)`; `OnTransportEvent` is the event-driven alternative to polling `PollEvent` every frame. | [NetworkTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkTransport.html) |

**Critical caveat**: `SinglePlayerTransport` cannot participate in the step-9 multi-client verification at all — its `StartClient()` unconditionally fails. Any real connectivity/ownership/RPC-direction check needs `UnityTransport`, whether direct IP/LAN or through Relay.

## Unity Relay setup

The NGO 2.13 manual page for Relay is a stub: it states the purpose ("connect clients and hosts over the internet using a relay server") and then defers entirely to Unity's separate Multiplayer Services (UGS) manual for the actual `RelayService`/allocation/join-code walkthrough — that content lives outside this NGO doc set and wasn't retrievable from the assigned page.

| Aspect | What it decides | Source |
|---|---|---|
| Purpose | NAT traversal without opening ports or running a public dedicated server — clients and the host both connect out to a relay allocation instead of directly to each other. | [Relay](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/relay/relay.html) |
| UnityTransport relay entry points | `SetRelayServerData(...)`, `SetHostRelayData(...)`, `SetClientRelayData(...)` — confirmed present on `UnityTransport` in 2.13. Call the host/server variant on the host after allocating, the client variant on each client after joining via the join code, and only then call `StartHost()`/`StartServer()`/`StartClient()`. | [UnityTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Transports.UTP.UnityTransport.html) |
| Encryption | Relay allocations are already secured at the relay layer — don't also set `UseEncryption`/`SetServerSecrets`/`SetClientSecrets` unless the project's specific Relay flow calls for double encryption. | [UnityTransport](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Transports.UTP.UnityTransport.html) |
| Non-Relay internet alternative | The FAQ lists Relay as one of three ways to connect over the internet, alongside a self-hosted cloud server with manually opened UDP ports, or a P2P transport (e.g. a Steam-based transport). | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |

**Documentation gap**: exact `SetHostRelayData`/`SetClientRelayData`/`SetRelayServerData` parameter lists, region selection, DTLS-vs-UDP connection-type strings, and the `RelayService.Instance.CreateAllocationAsync`/`JoinAllocationAsync`/join-code flow are not covered by the assigned NGO 2.13 pages — they live in Unity's Multiplayer Services (UGS) Relay manual, which the NGO relay.html page itself points to. Confirm those specifics there before wiring Relay into a feature.

## Testing locally and with artificial network conditions

### Local multi-instance testing

| Method | What it decides | Source |
|---|---|---|
| Player builds | Build via File > Build Settings > Build, then run multiple built instances side by side (optionally alongside the Editor that produced the build). Best for verifying actual target-platform behavior; build time makes it comparatively slow for tight iteration loops. | [Testing locally](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_locally.html) |
| Multiplayer Play Mode package | Simulates up to 4 players simultaneously on one dev machine, sharing the same source assets, entirely inside the Editor — no build step, and it still tests the real server-client relationship. | [Testing locally](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_locally.html) |
| ParrelSync | Third-party tool for running duplicate Editor instances (e.g. one clone as host/server, the primary Editor as client) without a full build. | [Testing locally](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_locally.html), [Techniques and tricks](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/techniques_and_tricks_for_debugging_multiplayer_games.html) |
| macOS: multiple instances of the same build | `open -n YourAppName.app` — each `-n` invocation launches a fresh, independent instance instead of focusing an existing one. | [Testing locally](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_locally.html) |

| `UnityTransport.SetDebugSimulatorParameters(int packetDelay, int packetJitter, int dropRate)` | Marked `[Obsolete]` in the 2.13 API — sets the three fields above in one call, but the API reference tells you to use the Network Simulator tool from the Multiplayer Tools package instead. | Release-build restriction | Simulator settings only take effect in the Editor or development builds — release builds ignore them entirely, so a release build can't be used to reproduce a latency-dependent bug. | [Testing with artificial network conditions](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_with_artificial_conditions.html) |

| Scope limitation | System-wide network-conditioning tools apply to every local instance at once — there's no built-in way to give only one of several local peers worse conditions than the rest. | [Testing with artificial network conditions](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_with_artificial_conditions.html) |
| Recommended test values (Boss Room reference) | ~100–150ms latency for desktop, ~200–300ms for mobile, 5–10% packet loss — a realistic floor to test at instead of only ever testing at 0ms/0% loss. | [Testing with artificial network conditions](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_with_artificial_conditions.html) |

### Testing client connection management

| Scenario | What to verify | Source |
|---|---|---|
| New connection | State replicates correctly to a client joining a fresh session. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |
| Reconnection / late join | A client rejoining an in-progress session, or joining late, ends up with the same state as clients present since the start; connection-approval denial is also handled cleanly rather than left half-connected. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |
| Graceful disconnect | A clean shutdown via `NetworkManager` correctly resets the state of every object tied to that session. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |
| Ungraceful disconnect | Application close and network-timeout disconnects both need to be exercised, not just the graceful shutdown path. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |
| Despawn without destroy | For a `NetworkBehaviour` that isn't destroyed on despawn (e.g. pooled), verify its state is actually reset — a stale value can silently survive into the next spawn. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |
| Host/server lifecycle | New-session init and shutdown, and whether state from before a session started leaks into a freshly started one. | [Testing client connection management](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/tutorials/testing/testing_client_connection_management.html) |

**Documentation gap**: this page frames scenarios as questions to verify, not as concrete API — it names no callback or response type (`OnClientConnectedCallback`, `ConnectionApprovalResponse`, etc.). Those live in the separate Connection Approval / Session Management manual pages, which this file doesn't cover; treat the table above as a test-scenario checklist rather than an API reference.

**Critical caveat**: none of the above — a single Editor Play Mode instance — exercises real network conditions, ownership boundaries, or RPC direction. A ClientRpc that's actually only running locally, or an owner-only check that never gets violated because there's no second peer, both pass silently in single-instance testing. Per SKILL.md §4's **"Verify with a real multi-client run before claiming the feature works"** directive, treat a feature as unverified until it has run as a real multi-client session (two builds, a build alongside the Editor, ParrelSync, or Multiplayer Play Mode's up-to-4-player simulation) or is covered by a `NetcodeIntegrationTest`, and layer in the artificial-conditions fields above so the run isn't only ever exercised at 0ms/0% loss.

## Troubleshooting and FAQ

| Symptom / question | Cause and fix | Source |
|---|---|---|
| `NullReferenceException` on `StartServer()`/`StartHost()`/`StartClient()` | No `NetworkManager` component exists on a scene GameObject — add one. | [Troubleshooting](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/troubleshooting.html) |
| `NullReferenceException` invoking a ServerRpc | The calling object was never spawned — call `NetworkObject.Spawn()` as the server first, per [spawning-objects.md](spawning-objects.md). | [Troubleshooting](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/troubleshooting.html) |
| Dedicated server build pegs a CPU core at 100% | Unity server builds push as many `Update` passes per second as possible by default — cap it, e.g. `Application.targetFrameRate = 30`. | [Troubleshooting](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/troubleshooting.html) |
| `"Can't find pending soft sync object. Is the projects the same?"` | Server and client scenes don't match — e.g. a `NetworkObject` exists on one side but not the other. Verify both editors/builds have identical scene content. | [Error messages](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/error-messages.html) |
| `"ArgumentNullException: Can't spawn null object Parameter name: netObject"` | `Spawn()` was called with a null `NetworkObject` reference — validate the reference before spawning. | [Error messages](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/error-messages.html) |
| `"[Netcode] Only owner can invoke ServerRPC that is marked to require ownership"` | A non-owner client called a `ServerRpc` marked `RequireOwnership` — gate the call client-side to the owning client, or drop `RequireOwnership` if that's not actually the intent. | [Error messages](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/error-messages.html) |
| `"KeyNotFoundException: The given key wasn't present in the dictionary."` | A `ServerRpc` executed on the host under conditions the server-side code didn't account for — add explicit ownership/server-state validation before the call proceeds instead of assuming the caller's state is valid. | [Error messages](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/error-messages.html) |
| `NullReferenceException` around `NetworkManager.Singleton` | `NetworkManager.Singleton` is null because no `NetworkManager` has been created/initialized yet in the current scene. | [Error messages](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/troubleshooting/error-messages.html) |
| Listen Server vs. Dedicated Server — does code change? | No — NGO supports both from the same code; branch on `IsServer`/`IsHost` rather than writing two separate code paths. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Does NGO include matchmaking? | No — a third-party matchmaking service is required; NGO only handles the transport/session layer once players are already matched. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| How do clients connect over the internet? | Three options: host on a cloud server, self-host with manually opened UDP ports, or use Unity Relay / a P2P transport (e.g. a Steam-based transport) to avoid port forwarding entirely. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Can `NetworkConfig`'s spawnable prefab list change after hosting starts? | Yes, but every client must add the identical object to its own configuration — a client missing the addition can't resolve spawns referencing it. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| How do clients on the same LAN find the host? | Use the host's local IPv4 address (Windows: `ipconfig`), not a public/internet address. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Best practice for physics | Simulate physics only on the server; on clients, remove/disable `Rigidbody` on non-owned objects and drive their transforms from replicated state instead, to avoid double-simulation stutter. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Steam transport setup | Add the Steam transport component and set `ConnectToSteamID` on the client — the FAQ states no further wiring is needed beyond that. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Windows "path too long" errors unzipping the Boss Room/Bitesize samples | Shorten the zip's filename to a single character and extract at the drive root (e.g. `C:\`), or extract with 7-Zip instead of Windows' built-in unzip. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| macOS "unidentified developer" warning on sample builds | Control-click the app → Open → approve in System Settings' Security pane, instead of double-clicking normally. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
| Why do samples use an `InitBootStrap` scene? | Keeps the `NetworkManager` singleton alive across scene loads, so it isn't destroyed when leaving a networked scene. | [FAQ](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/faq.html) |
