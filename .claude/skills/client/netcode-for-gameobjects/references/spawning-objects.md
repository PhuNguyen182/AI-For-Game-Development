Covers: SKILL.md §4 — **"Spawn and despawn through NetworkObject.Spawn/Despawn, pooled for anything frequent"**.

This file is the object's runtime lifecycle only — how a `NetworkObject` comes into network existence, gets pooled, gets hidden per-client, and goes out of existence again. Basic `NetworkObject`/`NetworkBehaviour` setup (the component itself, ownership model, `OnNetworkSpawn`/`OnNetworkDespawn`) lives in the sibling file [core-architecture.md](core-architecture.md) — read that first if the object doesn't exist yet.

## Spawn/despawn basics

| API | What it decides | Source |
|---|---|---|
| `NetworkObject.Spawn(bool destroyWithScene = false)` | Registers the instance with `NetworkSpawnManager` and replicates it to all clients. Default `destroyWithScene = false` means the object survives a scene unload unless explicitly told otherwise (`true` behaves like `Object.DontDestroyOnLoad` is *not* applied — the object is destroyed with the scene). | [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkObject.Despawn(bool destroy = true)` | Default `destroy = true` destroys the `GameObject` after despawning. Pass `false` to despawn from the network (remove from all clients) while keeping the local `GameObject` alive — this is the hook pooling relies on. | [Spawn/despawn manual](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/spawn-despawn.html), [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkObject.SpawnWithOwnership(ulong clientId, bool destroyWithScene = false)` | Spawns and immediately assigns ownership to `clientId` in one call, instead of spawning server-owned then transferring ownership after. | [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkObject.SpawnAsPlayerObject(ulong clientId, bool destroyWithScene = false)` | Spawns and registers the instance as `clientId`'s player object (`NetworkSpawnManager.GetPlayerNetworkObject`/`GetLocalPlayerObject` return it afterward). | [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkSpawnManager.InstantiateAndSpawn(NetworkObject networkPrefab, ulong ownerClientId = NetworkManager.ServerClientId, bool destroyWithScene = false, bool isPlayerObject = false, bool forceOverride = false, Vector3 position = default, Quaternion rotation = default)` | One-call instantiate + spawn helper; also resolves prefab overrides for you (`forceOverride` bypasses override resolution). Returns the spawned `NetworkObject`. | [Object spawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-spawning.html), [NetworkSpawnManager API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkSpawnManager.html) |
| Authority to call `Spawn` | Client-Server topology: only the server/host can spawn. Distributed Authority topology: any client can spawn and becomes that object's authority. | [Object spawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-spawning.html) |
| Requirement to spawn at all | The prefab needs exactly one `NetworkObject` component, at the prefab root, for its child `NetworkBehaviour`s to auto-associate with it. | [Object spawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-spawning.html) |
| Disabling GameObject children | You can't disable a spawning/despawning `NetworkObject`'s child GameObjects around the `Spawn`/`Despawn` call — doing so breaks the child `NetworkBehaviour` association step. | [Object spawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-spawning.html) |
| In-scene placed `NetworkObject`s | Spawn automatically once scene management is enabled on `NetworkManager` — no manual `Spawn()` call needed or expected for them. | [Object spawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-spawning.html) |

**Critical caveat**: never call `GameObject.Instantiate`/`Object.Destroy` directly on a network prefab as a substitute for `Spawn`/`Despawn`. A raw `Instantiate` never registers the instance with `NetworkSpawnManager`, so the object exists only on the local peer and never replicates. A raw `Object.Destroy` from a non-authority peer on a `NetworkObject` is explicitly documented as something that "should never" happen and causes exceptions — non-authority clients must go through `Despawn`, or through the registered `INetworkPrefabInstanceHandler.Destroy`, never a direct `Destroy` call.

## Network prefab handler

| API | What it decides | Source |
|---|---|---|
| `INetworkPrefabInstanceHandler.Instantiate(ulong ownerClientId, Vector3 position, Quaternion rotation) : NetworkObject` | Called **client-side only**, once per spawn of that prefab, on every non-authority client — replaces the default auto-instantiate step. Return the `NetworkObject` to use, or `null` if instantiation fails. | [Network prefab handler](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/network-prefab-handler.html), [INetworkPrefabInstanceHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.INetworkPrefabInstanceHandler.html) |
| `INetworkPrefabInstanceHandler.Destroy(NetworkObject networkObject) : void` | Called on **both** server and client: server-side when the object is destroyed or despawned with `destroy == true`; client-side when it receives a destroy message from the server/host. **Not invoked** if `Despawn(false)` is used — the handler is only responsible for cleanup on an actual destroy path. | [INetworkPrefabInstanceHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.INetworkPrefabInstanceHandler.html) |
| Who calls the authority-side `Instantiate` | The authority (server/host, or the spawning client in Distributed Authority) instantiates and spawns through normal user script logic directly — the handler's `Instantiate` runs only on non-authority receivers. | [Network prefab handler](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/network-prefab-handler.html) |
| `NetworkManager.PrefabHandler.AddHandler(...)` | Three overloads — key by `uint globalObjectIdHash`, by `NetworkObject prefabAssetNetworkObject`, or by `GameObject networkPrefabAsset` — all register `INetworkPrefabInstanceHandler instanceHandler` against that prefab's `GlobalObjectIdHash`. Must be registered before the prefab is ever spawned, i.e. set this up at startup, not lazily on first use. | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html) |
| `NetworkManager.PrefabHandler.RemoveHandler(...)` | Same three key overloads (`uint`/`NetworkObject`/`GameObject`) to unregister a handler. | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html) |
| `NetworkPrefabHandler.SetInstantiationData<T>(NetworkObject/GameObject, T instantiationData) where T : struct, INetworkSerializable` | Called on the **authority side before `Spawn()`** to attach custom data that flows through to the handler's data-aware `Instantiate` overload on receivers. If never called, receivers get `default(T)`. | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html), [NetworkPrefabInstanceHandlerWithData API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabInstanceHandlerWithData-1.html) |
| `NetworkPrefabInstanceHandlerWithData<T>` (abstract, `where T : struct, INetworkSerializable`) | Base class variant of the interface with `abstract NetworkObject Instantiate(ulong ownerClientId, Vector3 position, Quaternion rotation, T instantiationData)` — use this instead of the plain interface when the spawn needs extra per-instance data beyond position/rotation/owner. | [NetworkPrefabInstanceHandlerWithData API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabInstanceHandlerWithData-1.html) |
| Cleanup responsibility | Netcode does **not** auto-clean a partially initialized or pooled instance if instantiation errors out — the handler's `Destroy` is entirely responsible for returning/releasing whatever `Instantiate` created. | [Network prefab handler](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/network-prefab-handler.html) |
| `NetworkPrefabHandler.AddNetworkPrefab(GameObject prefab)` / `RemoveNetworkPrefab(GameObject prefab)` | Registers or unregisters a prefab with the handler's internal prefab bookkeeping directly, separate from `AddHandler`/`RemoveHandler` (which pair a prefab with an `INetworkPrefabInstanceHandler`). | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html) |
| `NetworkPrefabHandler.GetNetworkPrefabOverride(GameObject gameObject) : GameObject` | Resolves which prefab actually gets instantiated for `gameObject`, honoring any `NetworkPrefabOverride` configured on it (see the prefab registration table below) — call this instead of assuming the requested prefab is the one that spawns. | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html) |
| `NetworkPrefabHandler.RegisterHostGlobalObjectIdHashValues(GameObject sourceNetworkPrefab, List<GameObject> networkPrefabOverrides)` | Host-specific bookkeeping call that reconciles a source prefab's `GlobalObjectIdHash` against its registered overrides, so a host acting as both server and client resolves the same override consistently on both roles. | [NetworkPrefabHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabHandler.html) |

## Object pooling

| Aspect | What it decides | Source |
|---|---|---|
| How pooling is implemented | There is no separate pooling API — pooling *is* overriding the default spawn/destroy behavior via `NetworkPrefabHandler`/`INetworkPrefabInstanceHandler` (see table above). `Instantiate` pulls a deactivated instance from the pool and reactivates it instead of calling `GameObject.Instantiate`; `Destroy` deactivates and returns the instance to the pool instead of calling `Object.Destroy`. | [Object pooling](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/object-pooling.html) |
| When to pool | The manual names "often used objects, such as projectiles" as the target case — objects created/destroyed at high frequency, where avoiding repeated allocation/GC materially reduces CPU work. | [Object pooling](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/object-pooling.html) |
| Pool recycle mechanics | An object is deactivated after use; the next request for that prefab type recycles a deactivated instance and reactivates it rather than instantiating a new one. | [Object pooling](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/object-pooling.html) |
| Documentation gap | The pooling page itself is thin: it does not give exact method names beyond pointing back to the Network Prefab Handler page, does not state a registration-timing constraint beyond "before spawning," and does not describe pool sizing/growth policy. Treat the prefab-handler table above as the actual contract to implement against. | [Object pooling](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/object-pooling.html) |

**Critical caveat**: `Despawn(false)` on a pooled object deliberately skips the handler's `Destroy` (per the interface table above) — that's the correct call when a pooled projectile should return to an inactive state without the pool discarding it. Calling `Despawn(true)` (the default) on a pooled object routes into `Destroy` instead and defeats the pool unless `Destroy` itself is written to deactivate-and-return rather than actually destroy the instance.

## Prefab registration types

| Type | What it holds | Source |
|---|---|---|
| `NetworkPrefab` | One prefab registration: `Prefab` (GameObject asset), `Override` (`NetworkPrefabOverride`), `SourcePrefabToOverride` (GameObject, direct-reference override), `SourceHashToOverride` (uint, hash-based override for client builds missing the source asset), `OverridingTargetPrefab` (the replacement GameObject), plus read-only `SourcePrefabGlobalObjectIdHash`/`TargetPrefabGlobalObjectIdHash`. | [NetworkPrefab API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefab.html) |
| `NetworkPrefabOverride` (enum) | `None` — no override. `Prefab` — override the source prefab found via `SourcePrefabToOverride` (same-project direct reference). `Hash` — override via `SourceHashToOverride`, for when the server-side source asset doesn't exist in the client build. | [NetworkPrefabOverride API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabOverride.html) |
| `NetworkPrefabs` | Runtime registry on `NetworkManager.NetworkConfig`: `Prefabs` (read-only list), `Add`/`Remove(NetworkPrefab)`, `Contains(NetworkPrefab)`/`Contains(GameObject)`, `Initialize(bool)` to process the list for runtime use. | [NetworkPrefabs API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabs.html) |
| `NetworkPrefabsList` | A `ScriptableObject` asset holding a shared `PrefabList` (`IReadOnlyList<NetworkPrefab>`) that multiple `NetworkManager`s can reference — edits to the asset propagate to every `NetworkManager` pointing at it. Mutate only via its own `Add`/`Remove(NetworkPrefab)`, never by editing `PrefabList` directly. | [NetworkPrefabsList API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabsList.html) |
| Inline `NetworkConfig.Prefabs` vs. `NetworkPrefabsList` asset | Use the shared `NetworkPrefabsList` asset when more than one `NetworkManager`/scene needs the same prefab set (e.g. multiple test scenes, or a host/dedicated-server split project) — one asset edit updates every referencing `NetworkManager` instead of re-registering the same prefabs per manager. | [NetworkPrefabsList API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkPrefabsList.html) |

| API | What it decides | Source |
|---|---|---|

| `NetworkObject.NetworkHide(ulong clientId)` / static `NetworkHide(List<NetworkObject>, ulong clientId)` | Server-only: hides the object from one client — that client despawns/destroys its local clone and stops receiving traffic for it. | [Object visibility](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-visibility.html), [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkObject.IsNetworkVisibleTo(ulong clientId) : bool` | Query current visibility state for a given client without going through the delegate again. | [Object visibility](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-visibility.html) |
| `NetworkObject.SpawnWithObservers` | Set `false` before calling `Spawn()` to spawn the object with **no observers** — invisible to every client initially, instead of the default "visible to all." | [Object visibility](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/object-visibility.html) |

| Distributed Authority spawn latency | Any client can spawn locally without server mediation — "the client just spawns the projectile in the precise position desired relative to the player object," and transform changes on non-authoritative instances are network-tick-synchronized by the distributed authority service afterward. | [Spawning synchronization](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/spawning-synchronization.html) |
| Documentation gap | Neither the spawn-despawn index nor the synchronization page states explicit ordering guarantees across clients, late-joining client catch-up sequencing, or the exact payload sent on spawn — treat those as implementation details to verify against actual multi-client behavior, not documented contracts. | [Spawning and despawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/spawn-despawn.html), [Spawning synchronization](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/spawning-synchronization.html) |

## Deferred despawn (Distributed Authority only)

| API | What it decides | Source |
|---|---|---|
| Topology restriction | `DeferDespawn` is only available under the Distributed Authority topology — it does not apply to Client-Server. | [Deferred despawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/deferred-despawning.html) |
| `NetworkObject.DeferDespawn(int tickOffset, bool destroy = true)` | Delays the despawn on non-authority instances by `tickOffset` network ticks measured from the local client's current tick, instead of despawning immediately — used to let VFX/ragdoll/interpolation finish before the object actually disappears. `destroy` behaves the same as `Despawn`'s parameter once the deferred tick is reached. | [Deferred despawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/deferred-despawning.html), [NetworkObject API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.html) |
| `NetworkBehaviour.OnDeferringDespawn(int despawnTick)` | Authority-side callback fired when deferred despawn is initiated — the intended place to set final `NetworkVariable` state so it's captured before the defer-despawn message goes out. Non-authority sides pick up final state through normal `NetworkVariable.OnValueChanged` events, not a dedicated callback. | [Deferred despawning](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/basics/deferred-despawning.html) |
| `NetworkObject.OnDeferedDespawnCompleteDelegateHandler` | `public delegate bool OnDeferedDespawnCompleteDelegateHandler()` — no parameters, returns `true` to actually proceed with despawn once the deferred tick arrives, `false` to withhold it. Distributed-Authority-only, same as the rest of this section. | [OnDeferedDespawnCompleteDelegateHandler API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.NetworkObject.OnDeferedDespawnCompleteDelegateHandler.html) |
| `LocalDeferMode` (enum) | `Default` (falls back to `SendImmediate`), `Defer` (delay local execution to the next network tick), `SendImmediate` (execute locally without waiting). This enum governs **local Rpc execution timing**, not the `DeferDespawn` tick offset — `DeferDespawn` takes a plain `int tickOffset`, with no `LocalDeferMode` overload in 2.13. Listed here only because it sits next to deferred-despawn in the API surface; don't confuse the two. | [LocalDeferMode API](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.LocalDeferMode.html) |
