# Custom Post-Processing Effects in URP

Covers authoring a custom full-screen post-processing effect in URP: the low-code Full Screen Pass Renderer Feature workflow, the scripted Renderer-Feature-plus-Volume-Component workflow for exposing Volume-driven properties, injection points, and the underlying `ScriptableRendererFeature`/`ScriptableRenderPass` mechanism both workflows are built on.

## Manual
- [Custom post-processing in URP](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/post-processing/custom-post-processing.html) — landing page; presents two authoring paths (low-code Full Screen Pass Renderer Feature, and scripted Volume-Component-driven effect).
- [Create a low-code custom post-processing effect](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/post-processing/post-processing-custom-effect-low-code.html) — builds a grayscale effect from a Fullscreen Shader Graph + Material, added via a Full Screen Pass Renderer Feature with Injection Point set to "After Rendering Post Processing" and "Fetch Color Buffer" enabled — no C# required.
- [Create a custom post-processing effect with Volume support](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/post-processing/custom-post-processing-with-volume.html) — uses the `Assets > Create > Scripting > URP Post-process Volume Scripts` template to generate a `ScriptableRenderPass`/`ScriptableRendererFeature` script plus a `VolumeComponent` script, wiring Volume-authored properties (e.g. intensity) into shader values via `SetFloat` inside `AddRenderPasses`.
- [Full Screen Pass Renderer Feature reference](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html) — reference for the Renderer Feature used by the low-code workflow: injection timing (before/after transparents, after post-processing), buffer requirements (depth, normal, color, motion vectors), and material assignment via shader graph or SRP Blit template.
- [Fullscreen shader graph reference for URP](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/prebuilt-shader-graphs-urp-fullscreen.html) — reference for the Fullscreen Shader Graph material type used to author the Full Screen Pass Renderer Feature's material: Fragment context (base color, alpha, depth), Graph Settings (blend mode, depth test/write, stencil), and custom blend/stencil settings.
- [Inject a render pass using a Scriptable Renderer Feature in URP](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/renderer-features/scriptable-renderer-features/inject-a-pass-using-a-scriptable-renderer-feature.html) — the general mechanism both custom-post-processing workflows build on: subclass `ScriptableRendererFeature`, create the pass and set its `renderPassEvent` in `Create()`, then call `EnqueuePass` on the `ScriptableRenderer` in `AddRenderPasses()` every frame.
- [Injection points reference](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/customize/custom-pass-injection-points.html) — the set of predefined stages (shadows, prepasses, opaques, skybox, transparents, post-processing, etc.) a custom `ScriptableRenderPass` can be injected at.
- [Inject a render pass using the RenderPipelineManager API](https://docs.unity3d.com/6000.5/Documentation/Manual/urp/customize/inject-render-pass-via-script.html) — an alternative, narrower-scoped injection method (subscribing to `RenderPipelineManager.beginCameraRendering` and calling `EnqueuePass` on the camera's renderer directly); the page itself recommends using a Scriptable Renderer Feature instead for anything spanning multiple cameras/scenes/the whole project.

## Scripting API

Confirmed from fetched page content (package `com.unity.render-pipelines.universal@17.6` unless noted):

- [`UnityEngine.Rendering.Universal.ScriptableRendererFeature`](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.6/api/UnityEngine.Rendering.Universal.ScriptableRendererFeature.html) — base class added to a `ScriptableRenderer` to inject render passes; key members: `isActive`, `Create()`, `AddRenderPasses(ScriptableRenderer, ref RenderingData)`, `SetActive(bool)`, `Dispose()`, `OnCameraPreCull(ScriptableRenderer, in CameraData)`.
- [`UnityEngine.Rendering.Universal.FullScreenPassRendererFeature`](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.6/api/UnityEngine.Rendering.Universal.FullScreenPassRendererFeature.html) — the built-in Renderer Feature that creates a single-pass full-screen post-processing effect without writing code; key members: `passMaterial`, `passIndex`, `injectionPoint`, `requirements`, `fetchColorBuffer`, `bindDepthStencilAttachment`, `Create()`, `AddRenderPasses(ScriptableRenderer, ref RenderingData)`.
- [`UnityEngine.Rendering.Universal.ScriptableRenderPass`](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.6/api/UnityEngine.Rendering.Universal.ScriptableRenderPass.html) — implements a logical rendering pass used to extend the URP renderer (what a custom effect's Renderer Feature creates and enqueues); key members: `renderPassEvent`, `input`, `requiresIntermediateTexture`, `passName`, `ConfigureInput(ScriptableRenderPassInput)`, `RecordRenderGraph(RenderGraph, ContextContainer)`, `OnCameraCleanup(CommandBuffer)`.
- [`UnityEngine.Rendering.Blitter`](https://docs.unity3d.com/Packages/com.unity.render-pipelines.core@17.6/api/UnityEngine.Rendering.Blitter.html) — static utility class providing blit (texture copy) operations for Scriptable Render Pipelines, with support for scaling, filtering, and specialized operations such as octahedral mapping; used inside a custom `ScriptableRenderPass` to copy/composite the full-screen effect's source and destination buffers.
- [`UnityEngine.Rendering.RTHandle`](https://docs.unity3d.com/Packages/com.unity.render-pipelines.core@17.6/api/UnityEngine.Rendering.RTHandle.html) — a `RenderTexture` wrapper that scales automatically with camera size, enabling efficient render-target reuse across cameras of different resolutions; the handle type a custom post-processing pass reads/writes as its color/depth source and destination.

## Key concepts

- **Two authoring paths, one underlying mechanism.** Both documented workflows are built on the same `ScriptableRendererFeature` → `ScriptableRenderPass` → `EnqueuePass` injection pattern described in "Inject a render pass using a Scriptable Renderer Feature": `Create()` builds the pass and sets its `renderPassEvent`/injection point once, and `AddRenderPasses()` enqueues it into the frame loop every frame per camera.
  - **Low-code path**: `FullScreenPassRendererFeature` is a ready-made `ScriptableRendererFeature` — no custom C# pass is written. You author a Fullscreen Shader Graph, generate a Material from it, then assign that Material to the Renderer Feature and pick an injection point (e.g. "After Rendering Post Processing") and buffer requirements (e.g. "Fetch Color Buffer").
  - **Volume-support path**: uses the `Assets > Create > Scripting > URP Post-process Volume Scripts` template to scaffold a custom `ScriptableRendererFeature`/`ScriptableRenderPass` pair alongside a `VolumeComponent` script. The Renderer Feature's `AddRenderPasses()` reads the active `VolumeComponent`'s overridden parameters from the current `VolumeStack` and pushes them into the pass's shader (e.g. via `Material.SetFloat`), so the effect becomes tunable/blendable per-Volume like a built-in override.
- **Injection points** gate *when* in the frame a custom pass runs (shadows, prepasses, opaques, skybox, transparents, post-processing, etc.) — both the Full Screen Pass Renderer Feature and a hand-written `ScriptableRenderPass` choose one via `renderPassEvent`/`injectionPoint`.
- **Renderer Feature vs. `RenderPipelineManager` callbacks**: the Manual explicitly recommends the Renderer Feature pattern over subscribing to `RenderPipelineManager.beginCameraRendering` directly — the latter is presented as a narrower technique for one-off/per-camera injection, not the recommended way to ship a reusable custom post-processing effect.
