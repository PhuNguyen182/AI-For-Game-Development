# Ragdoll Physics — Ragdoll Wizard, Stability & Articulation Body

Covers SKILL.md step 7 (Articulation Body vs. Rigidbody+Joint chains) and step 8 (building/tuning ragdolls).

## Overview

A classic Unity ragdoll is a chain of Rigidbody-driven limbs connected by Character Joints, generated by the Ragdoll Wizard from a skinned mesh's bone hierarchy. Each joint is solved as an independent constraint between two Rigidbodies, so long chains (spine, arms, legs) can jitter or stretch when mass ratios or angular limits are poorly tuned, because the solver iterates pairwise rather than treating the whole chain as one system.

Articulation Body is Unity's alternative for jointed hierarchies: a single component that combines body and joint configuration and is solved as a hierarchical chain (reduced-coordinate formulation) rather than as independent constraints. This makes it markedly more stable for long kinematic chains — robotic arms, industrial mechanisms, and (where stability matters more than exact Character Joint semantics) ragdoll-like structures — at the cost of losing some Character-Joint-specific features (e.g. Character Joint's twist/swing limit authoring UX).

## Ragdoll Wizard workflow

| Step | Action |
|---|---|
| 1 | Import a skinned mesh character rigged with bones from a 3D modeling application into Unity (collider generation can be left disabled on import). |
| 2 | Drag the skinned mesh from the Project window into the Hierarchy to create an instance. |
| 3 | Open the wizard via **GameObject > 3D Object > Ragdoll…**. |
| 4 | Assign body parts by dragging each limb transform from the Hierarchy to its matching field in the wizard dialog. |
| 5 | Confirm/create the ragdoll — the wizard generates Box Colliders and Rigidbodies per body part, plus Character Joints connecting them, on top of the existing Skinned Mesh Renderer. |
| 6 | Review the generated components in the Inspector. |
| 7 | Enter Play Mode to verify the ragdoll behaves correctly. |
| 8 | Save the configured hierarchy as a prefab (**Assets > Create > Prefab**), then drag the ragdoll instance onto the prefab asset to finalize it. |

Character Joints created by the wizard use this axis naming convention: **Twist** rotates the limb along its own length; **Swing 1** and **Swing 2** are the two lateral swing axes.

## Joint & ragdoll stability guidance

| Recommendation | Why |
|---|---|
| Avoid very small non-zero Angular Y/Z limits on joints; keep a minimum of roughly 5–15 degrees, or set the limit to exactly zero to lock the axis. | Very small nonzero limits are a common source of jitter — either give the axis real range or remove it entirely. |
| Keep mass ratios between connected bodies modest (one body up to ~2x heavier than the other is safe). | Once one connected mass is ~10x larger than the other, the joint solver becomes jittery/unstable. |
| If connected Rigidbodies jitter, raise **Default Solver Iterations** to 10–20 in Physics settings. | More position-solver iterations resolve joint constraints more accurately per step. |
| If bounce responses look wrong, raise **Default Solver Velocity Iterations** to 10–20. | More velocity-solver iterations improve accuracy of bounce/impact resolution. |
| Disable **Enable Preprocessing** on the joint when it separates or moves erratically (e.g. a ragdoll spawned overlapping level geometry). | Preprocessing can produce unstable results when the joint's constraints can't be satisfied at spawn. |
| Enable **Projection** on Character Joint/Configurable Joint only for extreme cases of joint stretching. | Projection forcibly snaps the joint back into constraint compliance when the regular solver can't keep up, trading some physical accuracy for visual stability. |
| Never move a joint-connected Kinematic Rigidbody by writing its Transform directly; move it via the Rigidbody API instead. | Direct Transform writes bypass the physics pipeline and desynchronize the joint solver. |
| Avoid non-uniform scale on Rigidbodies/joints in the ragdoll hierarchy. | Non-uniform scaling causes collider/joint robustness issues in the physics solver. |
| Lower `maxDepenetrationVelocity` for bodies that start overlapping. | Produces smoother separation instead of an explosive pop-out when penetrating bodies are pushed apart. |

## Articulation Body — when to prefer it over Rigidbody+Joint chains

Articulation Body targets physics articulations built from hierarchically organized GameObjects — robotic arms and other kinematic chains — and is intended to deliver realistic behavior for simulation use cases such as industrial applications. Because the whole chain is solved together as one hierarchical system rather than as separate Rigidbody+Joint constraint pairs, it avoids the pairwise-solving instability (jitter, stretching, mass-ratio sensitivity) that long Rigidbody+Character-Joint chains are prone to, making it the more robust choice for deep or heavily loaded jointed hierarchies.

## Articulation Body component Inspector properties

| Property | Description |
|---|---|
| Mass | Mass of the body, in kilograms. |
| Immovable | Root-body-only setting that prevents the root from moving. |
| Use Gravity | Whether gravity affects this body. |
| Anchor Position / Rotation | Joint anchor position/rotation relative to this body. |
| Parent Anchor Position / Rotation | Joint anchor position/rotation relative to the parent body. |
| Compute Parent Anchor | Automatically synchronizes the parent anchor to match this body's anchor. |
| Snap Anchor to Closest Contact | Snaps the anchor to the closest contact point between the connected bodies. |
| Joint Type | Fixed, Prismatic, Revolute, or Spherical. |
| Linear / Angular Damping | Damping applied to the joint's linear/angular motion. |
| Joint Friction | Friction applied from relative motion of the parent body. |
| Axis (Prismatic) | The single translation axis allowed by a Prismatic joint. |
| Motion Type (Prismatic/Revolute) | Free or Limited motion along/around the joint axis. |
| X/Y/Z Drive | Per-axis drive properties (see ArticulationDrive fields below): lower/upper limits, stiffness, damping, force limit, target position/velocity. |
| Swing Y / Swing Z / Twist restrictions (Spherical) | Per-axis lock/limit configuration for a Spherical joint. |

## ArticulationJointType

| Value | Description |
|---|---|
| `FixedJoint` | Doesn't allow any relative movement of the connected bodies. |
| `PrismaticJoint` | Only allows relative translation of the connected bodies along one specified axis. |
| `RevoluteJoint` | Allows rotational movement around the X axis of the parent's anchor. |
| `SphericalJoint` | Only allows relative rotations of the two connected bodies. |

## ArticulationDrive fields

| Field | Description |
|---|---|
| `stiffness` | The stiffness of the spring connected to this drive. |
| `damping` | The damping of the spring attached to this drive. |
| `forceLimit` | The maximum force this drive can apply to a body. |
| `lowerLimit` | The lower limit of motion for a particular degree of freedom. |
| `upperLimit` | The upper limit of motion for a particular degree of freedom. |
| `target` | The target value the drive will try to reach. |
| `targetVelocity` | The velocity of the body this drive will try to reach. |
| `driveType` | Specifies which drive type to use for this drive. |

The drive follows a spring-damper model: `F = stiffness × (currentPosition - target) - damping × (currentVelocity - targetVelocity)`.

For Character Joint (the Rigidbody-chain ragdoll joint type) itself, see [joints.md](joints.md).
