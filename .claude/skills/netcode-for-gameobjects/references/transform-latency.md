Covers: SKILL.md §4 — **"Sync transforms with NetworkTransform, not hand-rolled position Rpcs"**.

This file is the decision reference for replicating Transform, Animator, and Rigidbody state over NGO 2.13: which helper component owns which job, the exact default thresholds/precision options that decide bandwidth vs. smoothness, how ticks and the network update loop order inbound/outbound processing, and when (rarely) client anticipation is actually justified over plain interpolated NetworkTransform. The `AttachableNode` API page (`Unity.Netcode.Components.AttachableNode.html`) returned 404 at fetch time; its facts below come from the manual page only.

## Helper components overview

| Component | What it decides | Source |
|---|---|---|
| `NetworkTransform` | Replicates position/rotation/scale per axis; owns the authority model (server vs. owner pushes updates), interpolation, and delta compression — this is the reason you never hand-roll a position RPC. | [Helper components](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/helpercomponents.html) |
| `NetworkAnimator` | Replicates Animator parameters/states/triggers; late joiners get current state/parameters but **not** triggers that already fired before they connected. | [Helper components](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/helpercomponents.html) |
| `NetworkRigidbody` / `NetworkRigidbody2D` | Forces the Rigidbody kinematic on every non-authoritative instance so physics simulates only on the authority; requires `NetworkTransform` on the same GameObject. | [Helper components](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/helpercomponents.html) |
| `AttachableBehaviour` + `AttachableNode` | Runtime parent/child attach-detach **without** `NetworkObject` parenting — avoids the nested-`NetworkTransform` hierarchy cost that reparenting under a `NetworkObject` would add. | [AttachableBehaviour](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/attachablebehaviour.html) |
| `ComponentController` | Enables/disables one or more components based on authority state (e.g. show a player's own avatar only to its owner); synchronized via RPC-driven field, not `NetworkVariable`, for delivery ordering. | [ComponentController](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/componentcontroller.html) |
| `RigidbodyContactEventManager` + `IContactEventHandler` | Centralizes collision/trigger contact dispatch for networked Rigidbodies so gameplay code doesn't hook Unity's per-object callbacks directly. | [IContactEventHandler](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.IContactEventHandler.html) |
| Physics (server-authoritative) | The authority Rigidbody is non-kinematic (physics simulates: velocities, collisions, forces); every non-authority instance is kinematic and just mirrors the authority's motion via `NetworkTransform`. | [Physics](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/physics.html) |

## NetworkTransform

### Core defaults

| Property | Default | What it decides | Source |
|---|---|---|---|
| `PositionThreshold` | `0.001` | Minimum position delta (world/local units) before a position update is even sent — below this, no bandwidth is spent. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `RotAngleThreshold` | `0.01` | Minimum rotation-angle delta before a rotation update is sent. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `ScaleThreshold` | `0.01` | Minimum scale delta before a scale update is sent. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `Interpolate` | `true` | Whether receiving instances smooth between state updates instead of snapping; toggling it at runtime forces a full resync ("teleport"). | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `UseUnreliableDeltas` | `true` (enabled) | Sends common state deltas unreliable-sequenced for better packet-loss tolerance; disabling forces reliable fragmented sequenced delivery for every update. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `InLocalSpace` | `false` | World-space vs. local-space synchronization. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `SyncPositionX/Y/Z`, `SyncRotAngleX/Y/Z`, `SyncScaleX/Y/Z` | all `true` | Per-axis opt-out of sync (e.g. a 2D game can disable Z). Disabled once `UseQuaternionSynchronization` is on — rotation axis checkboxes disappear. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html), [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| `AutoOwnerAuthorityTickOffset` | `true` (enabled) | Automatically compensates tick offset for owner-authoritative mode. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| `InterpolationBufferTickOffset` (static) | `1` tick (plus tick latency) | Extra buffer, in ticks, interpolation holds behind the newest received state before rendering it. | [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |
| Default `NetworkConfig.TickRate` | `30` ticks/sec | Baseline send frequency `NetworkTransform` operates against before any per-component override. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |

| Value | Meaning | Source |
|---|---|---|

### Interpolation types (`NetworkTransform.InterpolationTypes`)

| Value | Behavior | Source |
|---|---|---|
| `LegacyLerp` | Original NGO model: lerp between state updates, optional 2nd-phase lerp smoothing by `deltaTime / maxInterpolationTime`; can lose precision on sharp direction changes. | [NetworkTransform.InterpolationTypes](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.InterpolationTypes.html) |
| `Lerp` | Improved variant that maintains time-to-target under `InterpolationBufferTickOffset` when tick latency is high; smoothing rate = `1.0 - maxInterpolationTime`. | [NetworkTransform.InterpolationTypes](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.InterpolationTypes.html) |
| `SmoothDampening` | Smooth-damps toward current tick state by accumulated delta relative to time-to-target; optional 2nd-phase lerp smoothing; preserves smoothness at lower precision. | [NetworkTransform.InterpolationTypes](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.InterpolationTypes.html) |

### Precision / compression trade-off

| Mode | Bytes per rotation update | Notes | Source |
|---|---|---|---|
| Full precision (default) | 16 | No precision loss. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| `UseHalfFloatPrecision` | 8 | Position, rotation (unless quaternion compression also on), and scale use half-float (`HalfVector3`, 6 bytes for 3 axes); mid-level compression. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html), [HalfVector3](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.HalfVector3.html) |
| `UseQuaternionCompression` | 4 | "Smallest three" algorithm reduces a full quaternion to the size of a `uint`; ignores half-float precision settings; highest compression, slight precision loss. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html), [NetworkTransform (API)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkTransform.html) |

**Critical caveat**: `NetworkDeltaPosition`/`HalfVector3` half-float delta encoding clamps the **maximum position delta per update to 64 Unity world-space units** — at the default 30 Hz tick rate that caps supported speed at **1,920 units/second**; anything faster needs a lower `UseHalfFloatPrecision` reliance or a higher tick rate, or the delta silently misbehaves. Source: [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html).

### Full-resync ("teleport") triggers and gotchas

| Fact | Detail | Source |
|---|---|---|
| Runtime property changes force a teleport | Changing `UseUnreliableDeltas`, `InLocalSpace`, `Interpolate`, `SlerpPosition`, `UseQuaternionSynchronization`, `UseQuaternionCompression`, or `UseHalfFloatPrecision` at runtime re-syncs and resets interpolation for every value — visually a teleport. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| Periodic auto-correction | Even with `UseUnreliableDeltas`, a full axial resync happens once per second as a packet-loss safety net. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| `UseUnreliableDeltas` conflicts with reparenting | Cannot be enabled together with `SwitchTransformSpaceWhenParented`, since that feature needs deltas sent reliably. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| Nesting warning | "Exercise caution with the amount of nested `NetworkTransform`s in a network prefab, particularly if there will be many instances" — prefer `NetworkAnimator` or a time-based algorithm instead of nesting more transforms. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| Spawn-time parenting | Custom parenting on spawn must be set inside an overridden `OnNetworkSpawn()` **before** calling `base.OnNetworkSpawn()`. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| Owner-authoritative spawn order | Spawn with server authority first, then transfer ownership — switching authority mode at spawn time avoids a latency-driven visual anomaly. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
| Hierarchy attach point | A `NetworkTransform` must be on the `NetworkObject`'s GameObject or anywhere in its hierarchy generation below it; one `NetworkObject` can anchor multiple nested `NetworkTransform`s, none of which need their own `NetworkObject`. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |

## NetworkAnimator / NetworkRigidbody / attachables

### NetworkAnimator

| Fact | Detail | Source |
|---|---|---|
| What syncs | Current parameters/states, in-progress transitions, and parameter deltas each frame; triggers always sync when set `true`. Late-joining clients receive current state/parameters but not already-fired triggers. | [NetworkAnimator (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networkanimator.html) |

### NetworkRigidbody / NetworkRigidbody2D (via `NetworkRigidbodyBase`)

| Property/Method | Default | What it decides | Source |
|---|---|---|---|
| `UseRigidBodyForMotion` | `false` | When `true`, `NetworkTransform` reads position/rotation straight from PhysX during `FixedUpdate` instead of `Transform`. | [NetworkRigidbodyBase](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkRigidbodyBase.html) |
| `AutoUpdateKinematicState` | `true` | Automatically flips kinematic based on ownership/authority; disable only for a custom kinematic-state implementation. | [NetworkRigidbodyBase](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkRigidbodyBase.html) |
| `AutoSetKinematicOnDespawn` | not documented (manual frames it as useful for pooling) | Forces kinematic on despawn so a pooled/returned Rigidbody doesn't keep simulating. | [NetworkRigidbody (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networkrigidbody.html) |
| `MovePosition()` / `MoveRotation()` vs. `SetPosition()` / `SetRotation()` | — | The `Move*` pair moves smoothly (physics-interpolated); the `Set*` pair teleports directly. | [NetworkRigidbodyBase](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkRigidbodyBase.html) |
| `AttachToFixedJoint()` / `DetachFromFixedJoint()` | — | Authority-only fixed-joint connect/disconnect between two Rigidbodies (with mass, gravity, teleport options). | [NetworkRigidbodyBase](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/api/Unity.Netcode.Components.NetworkRigidbodyBase.html) |
| Requires `NetworkTransform` | mandatory | `NetworkRigidbody`/`NetworkRigidbody2D` has no sync of its own — it only manages the kinematic flag; `NetworkTransform` on the same GameObject still does the wire sync. | [NetworkRigidbody (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networkrigidbody.html) |

**Critical caveat**: avoid `UseUnreliableDeltas` on a `NetworkTransform` paired with `UseRigidBodyForMotion` — the manual states it "can impact the overall interpolation result." Also apply Rigidbody changes **after** `FixedUpdate`, not during `Update`/inbound-message processing: client input arrives during the `EarlyUpdate` network stage, which runs *before* that frame's `FixedUpdate` physics step, so mutating physics state too early produces jitter. Source: [NetworkRigidbody (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networkrigidbody.html), [Physics](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/physics.html).

## Latency, interpolation, and client anticipation

### Perceived-latency thresholds

| Threshold | Effect | Source |
|---|---|---|
| ~200 ms | The point where users start noticing gameplay degradation; framed elsewhere as making multiplayer feel "unplayable." | [Lag and packet loss](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/lagandpacketloss.html), [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| < 100 ms | The range FPS-genre games need to feel responsive. | [Lag and packet loss](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/lagandpacketloss.html) |
| Up to ~500 ms | RTS-genre games can tolerate this before gameplay is meaningfully impacted. | [Lag and packet loss](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/lagandpacketloss.html) |
| RTT/2 | Baseline delay: without any interpolation buffer, a client renders server state approximately half the round-trip time behind the server. | [Client-side interpolation](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/clientside-interpolation.html) |

### Latency-hiding techniques catalog

| Technique | What it does | Source |
|---|---|---|
| Client-side prediction | Client simulates the gameplay outcome of local input immediately, reconciling/correcting when the server's authoritative result diverges — the full version of what `AnticipatedNetworkTransform`/`AnticipatedNetworkVariable<T>` only partially provide. | [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| Action anticipation | Play a non-gameplay-impacting animation/sound/VFX immediately on input, while still waiting for the server-authoritative gameplay result. | [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| Extrapolation | Estimates a future state without accounting for latency; `NetworkTransform` includes basic extrapolation between the last server tick and the client-rendered frame. | [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| Server-side rewind (lag compensation) | Rewinds server state to the client's reported action timestamp to validate a hit, then corrects world state forward. Documented as **not currently implemented** — on the roadmap only. | [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| Controlled desync | Lets clients diverge briefly and reach a common end state via context-aware reinterpretation instead of a jarring correction snap. | [Dealing with latency](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/dealing-with-latency.html) |
| Client-side interpolation | Clients intentionally run slightly behind the server, buffering one state ahead so transitions render smoothly instead of snapping; implemented via `NetworkTransform` (`Interpolate` + `InterpolationBufferTickOffset`) — use it instead of a hand-rolled smoothing RPC. | [Client-side interpolation](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/clientside-interpolation.html) |

**Critical caveat**: the interpolation buffer/delay period **must stay shorter than the server's send interval**, or the buffer starves and the object visibly stutters waiting for the next update. Source: [Client-side interpolation](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/clientside-interpolation.html).

**Critical caveat**: this is the escalation gate for SKILL.md §4's **"Sync transforms with NetworkTransform, not hand-rolled position Rpcs"** directive and its YAGNI clause — do **not** reach for `AnticipatedNetworkTransform` / `AnticipatedNetworkVariable<T>` as a default replacement for plain `NetworkTransform`/`NetworkVariable`. Plain `NetworkTransform` with `Interpolate` on already hides ordinary RTT/2 lag smoothly. Anticipation adds real coordination cost — `StaleDataHandling` mode choice, manual `OnReanticipate` logic, `AnticipationCounter`/`ShouldReanticipate` bookkeeping — that only pays for itself once you've **measured** actual latency producing a **visible correction snap** (the anticipated value getting yanked back to the authoritative one) in real play, not before. See [state-sync.md](state-sync.md) for how `AnticipatedNetworkVariable<T>` otherwise behaves like, and diverges from, a regular `NetworkVariable<T>`.

## Ticks and the network update loop

### Ticks

| Fact | Detail | Source |
|---|---|---|
| Definition | A tick is one server simulation cycle: process client data received since the last tick, run simulation, send updated state to clients. | [Ticks and update rates](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/learn/ticks-and-update-rates.html) |

| Tick rate vs. update rate | Tick rate = how often the **server** updates game state; update rate = how often a **client** sends/receives. ### Why `NetworkTransform` beats a hand-rolled position RPC

| Fact | Detail | Source |
|---|---|---|
| `NetworkVariable`s (which `NetworkTransform` is built on) sync late joiners automatically | RPCs are documented as being for "event notifications" and requests that don't need to persist state for players who join later; state that must be consistent for both connected **and** late-joining clients is `NetworkVariable`'s job. | [Ways to synchronize](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/advanced-topics/ways-to-synchronize.html) |
| A hand-rolled position RPC has none of `NetworkTransform`'s machinery | No threshold-based dirty checking (`PositionThreshold`/`RotAngleThreshold`/`ScaleThreshold`), no delta compression (`NetworkDeltaPosition`/`HalfVector3`), no built-in interpolation (`BufferedLinearInterpolator<T>`), and no automatic full-resync recovery from packet loss — all of this is reimplemented work with strictly worse defaults than the shipped component. | [NetworkTransform (manual)](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.13/manual/components/helper/networktransform.html) |
